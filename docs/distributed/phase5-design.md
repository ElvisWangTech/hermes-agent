# Hermes 分布式改造 · Phase 5：部署、升级与回滚

> 版本：v3.0 ｜ 状态：待确认 ｜ 前置：[Phase 1](phase1-design.md)、[Phase 3](phase3-design.md)

---

## 1. 部署组件

| 组件 | 形态 | 说明 |
|---|---|---|
| 控制面（网关、Sandbox Manager） | 无状态服务，可多副本 | 首版单副本 + 单节点权威存储 |
| 权威存储 | 单节点 SQLite（首版）→ 托管 Redis 或数据库（多副本） | 切换需满足 Phase 1 的不回退假设 |
| 节点代理 | 每个 Cube 节点一个 | 管理节点目录、快照拷贝与恢复 |
| `apps/pocket-admin` | 独立服务 | 默认只绑定本机，远程访问须 HTTPS |
| 对象存储 | S3 兼容（默认七牛 Kodo） | 只存不可变快照 |
| Cube provider | 独立包，按版本矩阵部署 | 见 Phase 3 |

配置与密钥：

- 配置用镜像内的默认值加 `config.yaml`。
- 密钥用 Secret 或 `.env` 注入控制面。模型密钥只注入 VM（Phase 3）。

## 2. 模板版本与升级

- Cube 模板带版本号。旧 VM 不能在线挂载新模板的内容。
- 升级 = 按 profile 分批重建：快照 → 销毁 → 用新模板创建 → 恢复目录 → 健康检查。
- 每批有上限，失败即停止后续批次，已完成的批次保持。
- 快照清单带 `schema_version` 与 `min_reader_version`。新格式只在所有节点升级后才写入。N 与 N-1 版本在窗口内都能读取。

## 3. 排空

发布或维护前：

1. 控制面停止接收新会话，返回"维护中"。
2. 对所有运行中的实例做快照并暂停（或销毁）。
3. 确认快照清单已提交。未提交的实例列出清单。
4. 再进行控制面升级。

排空未完成时，不升级控制面。

## 4. 保留与删除

- 快照保留期：待定。超期对象按保留期清理。
- 角色销毁：立即删除实例、节点目录与控制面角色数据。快照与备份按保留期删除。文档中不承诺备份立即擦除。
- 日志中记录销毁操作，不记录数据内容。

## 5. 回滚

- 控制面回滚：切回上一版镜像。VM 继续运行，不受影响。
- 模板回滚：用旧模板版本重建。新格式清单在旧版本中不可读时，不得回滚到旧版本。
- 不提供"切回单体"的回滚路径。单体与 sandbox 的数据不互通。

## 6. 验收

1. 控制面单副本滚动升级：排空后升级，已暂停的 profile 在下次请求时唤醒，会话连续。
2. 删除单个控制面副本（多副本时）：其他副本接管，已有会话不中断。
3. 节点重启：节点目录完整，实例可恢复。
4. 模板升级分批执行：所有 profile 完成重建，会话可续聊；中途失败时停止且不丢数据。
5. 回滚演练：切回上一版控制面，数据可读。
6. 权威存储不可用：服务返回 503，不宣称成功。

## 7. 实施步骤

| 步 | 内容 | 验证 |
|---|---|---|
| S1 | 控制面镜像与首版部署（单节点） | 端到端：创建角色、连接、对话 |
| S2 | 节点代理部署与快照演练 | 验收第 3 条 |
| S3 | 排空流程 | 验收第 1 条 |
| S4 | 模板版本与分批升级 | 验收第 4 条 |
| S5 | 回滚演练与存储故障演练 | 验收第 5、6 条 |

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 批量重建造成唤醒拥塞 | 分批、限速、失败即停 |
| 模板版本不兼容 | 清单版本字段；N/N-1 窗口 |
| 排空遗漏运行中的实例 | 排空后逐个核对清单 |
| 单节点权威存储是单点 | 首版接受；多副本前切换托管存储 |
