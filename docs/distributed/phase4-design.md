# Hermes 分布式改造 · Phase 4：日程唤醒与观测

> 版本：v3.0 ｜ 状态：待确认 ｜ 前置：[Phase 1](phase1-design.md)、[Phase 3](phase3-design.md)
>
> 目标：角色的日程在 VM 暂停时也能按时执行，结果在用户下次打开或在线时送达。

---

## 1. 范围

- 只做日程与定时任务，服务 Pocket 的"到点提醒 / 到点去做"。
- 不做消息平台的 webhook 入站，不做出站回调队列。API 与网页入口是同步的。
- 不做外置 cron 存储或多节点选主。

## 2. 职责划分

| 数据 | 权威位置 |
|---|---|
| 日程定义（内容、重复规则、时区、是否暂停） | VM 内 cron 存储（节点目录，随快照） |
| 下次运行时间索引 | 控制面权威存储（派生，用于唤醒） |
| 已触发记录（occurrence） | 控制面权威存储 |
| 未听结果 | VM 内（节点目录） |

日程定义由 VM 写入。VM 每次修改后同步索引到控制面。

## 3. 到点流程

1. 控制面扫描到期索引。
2. 先在控制面写入 occurrence：`(profile_id, job_id, scheduled_instant)`，再进行后续步骤。
3. 若 VM 暂停，恢复 VM（Phase 3 唤醒流程）。
4. 派发任务给 VM。VM 执行任务，结果写入未听结果。
5. 任务结束后，VM 更新索引中的下次运行时间。

规则：

- **至多一次启动**：occurrence 在唤醒前已记录。崩溃后不自动重跑，标记为 `interrupted`。
- 唤醒失败：在补跑窗口内重试，窗口过后标记为"没做成"，不重复执行。
- 暂停或停用的日程不触发。继续后按原规则计算下一次，不补跑暂停期间错过的次数。
- 时间按该 profile 的 `timezone` 解释，为空则用服务器时区。

## 4. 未听结果与送达

- 结果先写入 VM 的未听记录，再决定如何送达。
- 页面在线且空闲：直接说出，作为角色主动说的一句，不写成用户说过的话。
- 页面在线但正在回合中：回合结束后补说，不打断。
- 页面未开：下次打开，按时间补说未听结果，一次最多三条。
- 页面在后台：浏览器通知由客户端发出。**通知不标记为已听。** 只有页面实际说出后才标记。
- 多台设备同时在线：只由一台说出，其他设备不重复播放，两边都能看到同一条结果。
- 没做成：说一次短句，原因记在该条日程上，不每周期重复。

送达逻辑在客户端与 VM 之间，控制面只负责转发。

## 5. 上限与配置

- 每个角色同时存在的未结束日程上限默认 20，由 `pocket.schedule_limit` 配置。超出时拒绝新增并说明，不替换旧条目。
- 改配置只影响之后的新增，不删除已有日程。

```yaml
cluster:
  observability:
    metrics_include_user: false
```

## 6. 销毁与停用

- 角色销毁：删除日程定义、索引与未听结果。
- 角色停用：暂停全部日程，不删除。重新授权后保持暂停，由用户逐条恢复。

## 7. 观测

- 沿用 `monitoring.export.otlp` 与现有配置门，不新建遥测栈。
- 指标：唤醒耗时、唤醒失败数、到点触发数、错过数、未听结果数量。
- 默认指标不带用户标签。`metrics_include_user` 显式开启后才带。

## 8. 验收

1. 实例暂停时，到点日程能唤醒 VM 并执行。
2. 同一 occurrence 在控制面崩溃后不重复执行。
3. 暂停后恢复不补跑；取消后不再出现。
4. 页面在线时到点说出，不写入用户发言。
5. 页面未开时，下次打开补说最多三条，两台设备不各念一遍。
6. 浏览器通知不标记已听。
7. 日程数超过上限时拒绝新增。
8. 两个角色的日程互不可见；伪造任务 ID 被拒绝。
9. 界面文案不出现 Hermes、cron、profile（由 `apps/pocket` 保证，此处列为验收项）。

## 9. 实施步骤

| 步 | 内容 | 验证 |
|---|---|---|
| S1 | 索引与 occurrence 的权威存储 | 同一 occurrence 只记录一次 |
| S2 | 到点唤醒与派发 | 暂停实例被唤醒执行 |
| S3 | 未听结果与送达规则 | 第 8 节第 4、5、6 条 |
| S4 | 上限、暂停、销毁与停用 | 第 8 节第 3、7 条 |
| S5 | 指标与配置门 | 默认无用户标签 |

## 10. 实现状态（2026-10-31）

`gateway/coordination/schedule.py`。

- `FileScheduleSource`：只读取各 profile 节点目录下的 `cron/jobs.json`，筛出已启用且 `next_run_at` 已到期的任务。
- `OccurrenceLedger`：在唤醒前原子认领 `(profile, job, scheduled_instant)`，同一次到期只认领一次；控制面重启时把遗留的 `claimed` 标为 `interrupted`，不重试。
- `WakeScheduler.tick`：认领后调用 `InstanceManager.ensure_running`，成功记为 `woken`，失败记为 `failed`。它只负责唤醒，任务本身由实例内的 cron 调度器执行，并依靠其自身的账本防止重复触发。

未实现：

- 控制面的周期调度循环（tick 需要外部定时器）。
- 失败的唤醒在补跑窗口内的重试（当前失败即结束）。
- 未听结果的送达与日程界面的接线（属于 `apps/pocket` 与 Pocket 日程模块，本阶段不改）。
- 依赖实例内 cron 账本的"唤醒后即执行"尚未在真实实例上验证。
