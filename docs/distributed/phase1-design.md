# Hermes 分布式改造 · Phase 1：快照与实例租约

> 版本：v3.0 ｜ 状态：待确认 ｜ 前置：[Phase 0](phase0-design.md)
>
> 目标：实例销毁、节点故障后，profile 的状态能在新实例中恢复到最后一次成功快照；旧实例不能再写入。

---

## 1. 快照

### 1.1 方式

快照在 **VM 暂停时** 由节点代理完成：

1. 暂停 VM。
2. 节点代理拷贝 `/root/.hermes` 与 `/workspace` 对应的节点目录，打包为 zstd 压缩的 tar。
3. 上传对象存储，得到 `sha256`。
4. 控制面提交清单（见 1.3）。
5. 恢复 VM（如果不是销毁流程）。

不在 VM 内导出 SQLite，也不做运行中拷贝。运行中拷贝有 WAL 与一致性风险。

VM 内不持有对象存储凭证，上传由节点代理完成。

### 1.2 触发

| 触发 | 条件 |
|---|---|
| 空闲暂停 | 每次 pause 前 |
| 销毁 | 每次 destroy 前 |
| 排空 | 发布或维护时 |
| 周期 | 距上次快照超过 `snapshot_interval_sec`（默认 600s），且 VM 上报过活动 |

周期快照会打断一次运行。默认间隔与暂停耗时需实测后定。

### 1.3 清单

清单存控制面权威存储，字段：`profile_id`、`instance_id`、`revision`（单调递增）、`object_key`、`sha256`、`size_bytes`、`schema_version`、`min_reader_version`、`created_at`。

### 1.4 提交

- 提交是一次条件更新：仅当 `instance_id` 仍持有有效租约，且 `expected_revision` 等于当前清单版本时，才发布新清单。
- 上传成功但提交失败，只留下孤儿对象，不构成快照。孤儿对象按保留期清理。
- 上传或提交失败时，保留 VM 当前状态，不销毁，下次触发重试。

### 1.5 大小

- 工作区与目录总大小有上限（按 profile 配置，默认值待定）。超限时拒绝扩大快照，并通知管理员。
- 排除 `__pycache__`、`.pytest_cache` 等可再生成目录，以及所有符号链接（技能覆盖层在 VM 启动时重建）。

## 2. 恢复

1. 控制面选择一个节点，节点代理下载清单指定的对象。
2. 校验 `sha256`，失败则拒绝恢复，不回退到更旧版本（除非管理员显式选择）。
3. 解压到**空的**节点目录。已存在的旧目录先整体移动到隔离位置，不直接删除。
4. 创建 VM 并挂载该目录（见 Phase 3）。

恢复是目录级替换，不做 SQLite 合并，不需要 replace 导入。

## 3. 实例租约与 fencing

- 每个 profile 同一时刻只有一个有效实例（`instance_id`）持有租约。租约由 Sandbox Manager 维护，带 TTL，定期续约。
- **单 writer 约束**：新实例挂载目录前，旧实例必须已停止，或其租约已过期且 VM 已确认停止。双挂载会损坏 `state.db`。
- 续约失败时，Manager 停止该实例的路由，并请求节点代理停止 VM。
- 旧实例的快照提交因租约失效而被拒绝（1.4）。

## 4. 故障

| 故障 | 结果 |
|---|---|
| 节点硬故障 | 从最后成功快照恢复到新节点。之后的修改丢失 |
| VM 异常 | 保留节点目录，重建 VM |
| 快照上传失败 | 不提交，保留 dirty 状态，下次重试 |
| 清单提交冲突 | 拒绝，旧实例不再写入 |
| 对象校验失败 | 拒绝恢复，告警 |

## 5. 验收

1. 销毁后在新实例恢复：会话、记忆、私有 Skill、配置、工作区、日程一致。
2. 杀掉节点后，在另一节点恢复到最后成功快照；快照之后的修改丢失且被记录。
3. 旧实例在新实例持有租约后提交快照，必须被拒绝。
4. 双挂载尝试被阻止。
5. 对象篡改后恢复被拒绝。
6. 暂停/快照/恢复循环 N 次后，`state.db` 完整性检查通过。
7. A→B→A：profile 的数据不串用，两个 profile 之间互相不可见。

## 6. 实施步骤

| 步 | 内容 | 验证 |
|---|---|---|
| S1 | 清单存储与条件提交 | 并发提交只有一个成功 |
| S2 | 暂停拷贝快照与上传 | 快照可校验 |
| S3 | 恢复与隔离旧目录 | 销毁重建后数据一致 |
| S4 | 租约与 fencing | 旧实例提交被拒绝 |
| S5 | 周期快照与暂停耗时实测 | 确定默认间隔 |

## 10. 实现状态（2026-10-31）

已在 `gateway/coordination/` 实现，并替换原共享拓扑代码（SessionRouter、Redis 路由、节点反代、drain HTTP、日志四元组）：

| 模块 | 内容 |
|---|---|
| `authority.py` | `ControlPlaneAuthority`：实例租约（acquire/renew/release/require）、dirty 标记、清单条件提交。所有写入在 `BEGIN IMMEDIATE` 事务内校验租约 |
| `snapshots.py` | `SnapshotService`：snapshot（暂停→打包→上传并回读校验→条件提交→恢复）、snapshot_if_due、restore（校验哈希后整体替换，旧目录隔离保存）、drain |
| `archive.py` | 打包/解包；拒绝链接、绝对路径、`..`，限制大小 |
| `objects.py` | S3 兼容对象存储；写后读校验 |
| `host.py` | `NodeHost` 协议：目录、pause/resume/stop。Phase 3 实现 |
| `config.py` | `cluster.*` 解析与启用前检查 |

测试：`tests/gateway/coordination/`（11 个），覆盖租约互斥与隔离、条件提交、快照→恢复、上传失败不提交、僵尸实例被停止、对象校验失败不覆盖本地、排空、大小限制。

未实现（按 Phase 划分）：

- `NodeHost` 的 Cube 实现（Phase 3，独立包）。
- 排空的 HTTP 入口（排空由控制面调用，入口在 Phase 5 的部署中接线）。
- `uv.lock` 尚未重新锁定：移除 redis、增加 zstandard 后需在有网络时执行 `hermes pm lock`。
