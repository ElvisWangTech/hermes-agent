# Pocket 后台管理：需求与页面方案

> 2026-10-12 / 初稿及实施记录。对应 [Pocket 主设计](design.md)；视觉稿与产品边界先行，已实现部分另见下方实施留痕。
>
> 第一阶段为单机、基于 profile 的管理台；声纹识别和用户自助销毁仍在第二阶段。路由、认证复用方式和持久化格式是实施前待确认项，不代表现有服务已支持。

## 首版视觉稿（2026-10-12）
### 最新实施边界

管理后台已拆为独立项目 `apps/pocket-admin`，独立构建和服务端口，默认地址 `http://127.0.0.1:9122/`。旧 `/pocket/admin` 方案废止。必须通过独立管理员密码登录后才能访问管理数据和签发接口，不接受客户端设备凭证或 Web 全服务令牌。部署与初始化见 [独立管理项目说明](../../apps/pocket-admin/README.md)。

当前实现包含既有独立 profile 的签发与授权撤销，以及独立 profile 的模型配置入口；下文旧稿的完整创建、销毁、审计或在线状态仍未实现。当前码只能管理员签发；用户申请和账号系统为后续阶段，不开放匿名或设备签发。正式部署采用独立主机名及 HTTPS，不能只靠不同端口隔离 Cookie。

已检查桌面列表、移动列表和销毁确认的渲染输出，并检查列表、详情和对话框的内容边界；详情页按内容延长，避免底部操作被裁切。该稿是静态视觉草案，不是可点击流程原型，也未连接后台。下一轮评审需补齐连接码签发后的单次展示与二维码、重新验证后的最终销毁确认、凭证详情，以及移动端导航和其他页面；管理员认证和备份策略确认后，才进入实现。

## Profile 配置实施留痕（2026-10-12）

### TTS 保存补充

- Pocket 的未配置 Edge voice 默认改为中文晓晓；默认值仅作用于 Pocket，不改 Hermes 全局默认。已有显式声音保留。Edge voice 改用带语言和名称的下拉列表，保留未知已配置声音选项；其他 provider 保持原配置方式。
- 新 profile 的安全语音快照显式保留复制字段，避免默认值裁剪使原声音选择消失。临时 home 测试验证中文回退、保留英文选择及不同 profile 的声音隔离。

- Admin 保存时为显式提交的 STT/TTS 标量字段与 provider 子字段传入 `save_config(..., preserve_keys=...)`。原先与系统默认值相同的新字段会被默认值裁剪省略，造成 YAML 中看不到用户选择；现在显式选择即使等于默认值也会写盘，未提交的高级设置仍保留。
- 回归测试直接解析临时 profile 的配置 YAML，确认默认 TTS provider 与默认声音实际存在；Admin 四项测试通过。部署需重启 Admin 后重新保存；此修复针对配置持久化，不代表进行中的语音会话立即重载配置。

### 凭据配置补充

- Admin 新增 `GET /api/pocket/profiles/{profile}/credentials` 和单槽位 `PUT/DELETE /api/pocket/profiles/{profile}/credentials/{key}`。仅独立命名 profile 可操作，受现有管理员 cookie 与同源写保护约束。
- UI 提供密码输入、槽位状态、独立保存与确认删除；空输入不改动现有凭据。读取仅返回布尔状态，校验错误统一返回通用消息，防止 FastAPI 默认校验响应回显敏感输入。
- 写入与删除复用 `hermes_cli.credential_lifecycle`，不手工拼接 dotenv，不复制 default 密钥。标准 Chat Completions key 更新复用已有轮次边界客户端刷新，保持提示词与工具缓存不变；不承诺其他传输、OAuth、自定义路由、failover 与删除的存活客户端即时刷新。
- 临时 home 测试覆盖真实写入、独立子进程读取、A→B→A 隔离、旧 secret scope 快照保留、客户端重建调用、登录保护与无明文响应。子进程测试使用两个独立读取进程，尚未覆盖同一个长驻进程的缓存复读或真实 provider HTTP 调用；不将这些测试声明为完整线上 E2E。相关两文件合计 22 项测试通过。

根据“新 profile 需要继承必要配置，并可在 Pocket 后台修改”的需求，已在独立管理服务中落地以下约定：

- 新 profile 在签发连接码时创建；创建完成后从 `default` 复制主模型、上下文长度及 STT/TTS 安全字段，复制发生一次，之后 profile 保持独立，不做运行时回退或动态继承。
- 只复制模型选择本身，不复制 `default` 的 `.env`、API 密钥、OAuth 凭据、消息渠道、记忆、会话或其他用户身份数据。新 profile 的秘密仍需通过其自身的 secret scope 配置。
- Admin 新增“Profile 配置”入口。provider 使用下拉，模型名称使用可手动输入的候选框，候选随 provider 联动；现有目录外模型值保留。支持 STT 开关、语言及 STT/TTS provider、模型和声音字段；`default` 不作为可编辑目标。
- `GET /api/pocket/profiles/{profile}/options` 复用 Hermes 模型目录，仅返回名称与模型列表，不返回连接配置。手动填写的新模型仍接受 Hermes 原有选择校验；模型/provider 未变时不重复目录校验，避免阻塞语音或上下文保存。上下文写入规范位置 `model.context_length`。
- 读取和写入接口为 `GET/PUT /api/pocket/profiles/{profile}/config`，继续使用现有 profile scope、模型选择校验、配置 mutation lock 和 `save_config` 原子写入，不直接拼接或覆盖 YAML。
- 语音只允许基础非秘密字段，不复制密钥、自定义执行命令或参考文件路径；保存保留目标 profile 原有高级配置。此入口不代表角色销毁、审计或在线状态已完成。provider 所需密钥不会自动授予新 profile。
- 验证：临时 home 的真实 profile 创建与配置读写测试覆盖 A→B→A 隔离、目录外原模型保存、语音更新与秘密拒绝；测试使用项目内解释器，不在用户目录初始化依赖。

对应实现位于 `apps/pocket-admin/server.py` 与 `apps/pocket-admin/src/Admin.tsx`；运行说明和安全边界同步记录在 [Pocket Admin 独立项目说明](../../apps/pocket-admin/README.md)。

## 定位与范围

使用者是部署和维护 Pocket 的管理员，不是正在与角色聊天的主人。后台处理角色从创建、激活、重新连接到销毁的生命周期；手机端继续保持一个对话主画面。

第一阶段包含：创建独立 profile、签发和撤销连接码、查看激活进度、撤销访问凭证、核实并人工销毁角色、查看脱敏操作记录和基础服务状态。不提供聊天界面、读取会话正文、查看普通记忆、查看完整主人介绍、代用户起名、换形象、转让主人、声纹管理、批量销毁、模型商店或集群调度。

后台采用中文文案，界面标题为「Pocket 管理」。它不是手机端内的一层设置，也不能由普通 Pocket 凭证打开。页面和管理 API 由独立管理服务提供，必须逐请求检查管理员登录会话。

## 页面结构

桌面端用窄侧栏和主要内容区，导航只有「角色」「连接码」「操作记录」「服务状态」。顶部展示当前管理员、单机部署标识和退出入口，不做欢迎页或大面积统计卡片。

默认进入角色列表。角色数量、待激活数和异常数用紧凑文字摘要呈现，主要空间留给可筛选列表。详情为独立页面，有明确返回入口；创建、签发码和确认操作使用抽屉或对话框。

手机管理端保留相同信息架构，导航收为菜单；角色列表改为紧凑条目，显示名字、短 ID、生命周期和连接状态，点击进入完整详情。危险操作不藏在横向溢出区，不与复制、刷新相邻。点击区域至少 44px。

### 1. 角色列表（首页）

顶部有按角色名字、主人称呼、稳定 ID 搜索的输入框，生命周期筛选和「创建角色」按钮。筛选后数量与列表来自同一查询，翻页不重置筛选。

每行显示：随包画像小缩略图（未选时使用中性占位图标）、角色名字或「未起名」、稳定 profile ID、主人称呼或「未认主」、生命周期、连接数、当前回合状态、最近活动时间。名字可能重复，所有操作都以稳定 ID 为目标。列表不展示凭证明文、主人的完整介绍、会话内容或本机绝对路径。

生命周期与在线状态分开显示：已激活不代表在线，离线不代表故障。当前回合只显示空闲、在听、思考、说话、待确认等实际可观测状态；无法获取时显示「未知」，不能猜测。多会话时显示活跃回合数，不把某一个会话状态冒充整个角色状态。

行内只有「查看」等低风险操作；签发码、撤销访问和销毁进入详情。初次无角色时显示「创建角色」入口；加载失败保留筛选，显示重试，不把失败渲染成空列表。

### 2. 创建角色

创建抽屉只要求管理员填写可选内部备注，并确认独立 profile 的配置来源。稳定 ID、home 和专属工作区由后台生成，不接受浏览器提交文件路径。内部备注不作为角色名字，不进入提示词。

第一阶段采用管理员维护的显式基础配置模板；只复制允许的配置，绝不克隆默认 profile 的记忆、会话、主人、声纹或用户凭证。模型和语音服务凭证如何为新 profile 配置须沿用现有 secret scope 并在实施前确认，不能通过复制默认 `.env` 隐式授予权限。

提交后进入「创建中」，成功跳转角色详情并提示签发激活码。重复点击和请求重试使用幂等操作标识，不生成多个 profile。配置不完整时标记「创建失败」及脱敏原因，提供同一操作的重试；失败半成品不得签发连接码，也不得落到默认 profile 继续执行。

### 3. 角色详情

顶部显示画像、名字、稳定 ID、生命周期和连接概况。三个页签为「概况」「连接与凭证」「管理记录」，不嵌套一层层卡片。

「概况」展示激活进度：连接码已兑换、形象已选择、名字已确认、主人已确认、记忆已提交、激活完成。数据以后台持久化状态为准，不通过是否存在名字猜测成功。主人区域只显示称呼、绑定时间及「授权绑定，未做声纹验证」；第一阶段不出现假的声纹开关。管理员不能编辑角色名字、形象或主人介绍。

「连接与凭证」显示连接码元数据、凭证 ID、签发/最近使用时间、状态和当前连接数，不显示已签发凭证明文，也不把设备备注当成真实硬件身份。支持撤销单个凭证和撤销该角色全部访问。撤销需确认影响范围；后台拒绝后续请求并断开相应连接，取消由该凭证发起的未完成回合，不能撤销后仍保留可操作的 WebSocket。若连接数无法确认，标记未知。

「管理记录」仅显示本角色的操作记录。脱敏故障可关联操作 ID，不能直接打开原始日志中的密钥、录音或聊天内容。

页面底部为独立「危险操作」区，第一阶段提供管理员销毁，不提供重置认主、恢复为默认角色或直接编辑 profile 文件的入口。

### 4. 连接码

全局列表按目标角色、用途和状态筛选；显示码记录 ID、角色 ID、用途（首次激活 / 重新连接）、签发时间、到期时间、兑换时间和状态。状态为有效、已兑换、已过期、已撤销；列表不显示码明文，也不允许再次查看已签发明文。

签发对话框显示目标角色的名字与完整稳定 ID。首次激活码只能用于未激活角色；重新连接码只能用于已激活角色，关联既有主人授权，不重新走起名认主。管理员必须先核实重新连接申请，任何拿到重新连接码的人都可能取得该角色访问权，不能将其当成无风险分享链接。

建议默认有效期 10 分钟，可选 5、10、30 分钟，以配置限制上限。每个角色同一用途最多一个有效码；重新签发前明确告知旧码将失效，并在同一事务中撤销旧码、创建新码。已兑换码不能恢复。

成功后一次展示连接码、到期时间、复制按钮和二维码；关闭后不再展示明文，遗失只能重签。二维码包含可信 HTTPS 入口和短时兑换材料，不包含长期访问凭证。浏览器 URL 和跳转清理、Referrer 防泄露及日志脱敏需在接口契约中明确；不能在页面永久显示带码链接。已撤销或已兑换时，当前展示页及时失效。

首次激活码兑换后如果引导中断，原访问凭证可恢复同一激活进度。凭证丢失时，第一阶段由管理员撤销旧授权并签发绑定同一 profile 的恢复码，保留已确认进度且不覆盖已绑定主人；恢复码作为单独用途，不能重新把连接码标为未兑换。

### 5. 管理员销毁

这是第一阶段的后台人工处置入口，不是用户自助销毁，也不标记「主人声纹已通过」。管理员权限意味着可以删除该部署中的角色，不等于管理员就是角色主人。

流程如下：

1. 从目标角色详情进入销毁，显示画像、名字和完整 ID；必须填写核实方式与处置原因，不记录无关个人信息，也不能只因填写了原因就声称已验证主人。
2. 后台预检并列出删除范围：专属会话、记忆、绑定记录、凭证、连接码、专属配置/密钥、工作区，以及第二阶段可能存在的声纹。共享画像、共享配置资源和其他 profile 明确排除。无法确定目录归属时阻止删除，不接受前端路径或任意递归删除。
3. 列出活动回合、后台任务、待处理审批和备份保留情况；说明停止范围及不可逆后果。管理员重新验证自己的管理会话，输入目标稳定 ID并点击「永久销毁」。输入 ID只防误点，不当成身份认证。
4. 后台创建持久化操作记录并将角色置为「销毁中」，立即禁止新请求、撤销全部入口，然后停止任务、释放 profile-scoped 缓存、删除专属数据。操作在客户端断线后仍继续，重复确认不启动第二次删除。
5. 进度页显示阻断访问、停止任务、删除数据、完成四步及实际结果。无法停止任务或删除失败时保留阻断状态，标记「销毁失败」，允许管理员对同一操作重试，不恢复激活、不宣称完成。

成功后保留最小销毁墓碑和脱敏审计（稳定 ID、操作人、时间、原因、结果），不保留角色名字、主人介绍、会话、密钥或声纹。保留期限按部署策略确定；备份仍存在时明确显示预计清除时间，恢复旧备份必须重新应用吊销/销毁记录，防止复活旧身份。实际销毁与墓碑留存规则须先设计确认。

第二阶段主人自助销毁走主设计的声纹流程。管理员人工销毁继续独立标记，不提供「跳过声纹并视为主人验证成功」的开关。

### 6. 操作记录

记录创建角色、签发/撤销/兑换码、确认主人、签发/撤销凭证、恢复激活进度、启动/重试/完成销毁，以及管理登录等安全事件。字段包含时间、管理员或用户主体类型及不透明 ID、目标 profile ID、操作、结果、原因码和操作 ID。

支持按时间、角色、操作者类型、操作与结果筛选。记录采用服务端时间，不依赖浏览器报告的成功状态；关键操作的审计与状态提交必须一致，审计无法持久化时拒绝高风险变更。不记录连接码、token、secret、原始音频、声纹模板、完整介绍或对话正文。

第一阶段不做全量日志浏览和导出，避免未经确认扩张敏感数据访问面。操作记录存储范围、管理员审计权限和保留期限在实施前确认。

### 7. 服务状态

显示 HTTPS 入口、后端连接、profile 存储可写性、听写/朗读服务配置与最近实际结果，以及配置缺失、磁盘不足、销毁失败等待处理异常。配置已填不等于服务可用，未探测显示「未验证」；管理员手动语音测试须明确会调用外部服务及可能产生费用，不自动录音。

第一阶段声纹标记「第二阶段，未启用」，不提供不可用开关。状态页不展示密钥和服务器私有路径，不复制现有完整配置控制台；修改 provider、模型、工具和 secret 仍沿用现有管理方式。异常可跳到对应角色或操作记录。

## 状态与权限契约

角色生命周期为创建中、创建失败、待激活、激活中、已激活、销毁中、销毁失败、已销毁。连接/回合状态是另一维度。连接码过期不让已激活角色退回待激活；撤销访问凭证不抹掉主人；销毁中/失败不允许签发新码。已销毁稳定 ID不能复用给新角色。

后台只管理显式登记为 Pocket 专属的 profile，不能列出机器上所有 profile 后默认赋予删除权限。已有 profile 的纳管需单独设计，不在第一阶段加入任意路径导入。

第一阶段采用部署管理员单一权限，不先做账户系统或复杂 RBAC。管理认证必须独立于 Pocket 的角色访问凭证及激活码，优先复用已有服务的管理员认证机制；若现有机制只有普通用户 token，则必须先补管理权限契约，不能直接将它升级为管理员。初始管理员凭证由本机部署流程建立，不经公开网页自助注册。

默认仅本机访问管理入口；远程管理须显式启用可信 HTTPS 和管理认证，不能因为 Pocket 手机入口已对局域网开放就同步开放后台。管理会话使用短时有效、可退出/撤销的安全 cookie，不放 URL 或普通 localStorage；写操作校验 CSRF 与 Origin。具体认证接入在编码前确认，不新增核心模型工具。

后台每个请求校验权限和目标 profile，后台任务及线程显式绑定 profile scope。普通用户请求伪造管理路由、目标 ID或管理员字段均拒绝。前端隐藏按钮不是安全边界。

## 视觉与反馈

白色主内容、浅灰结构背景、石墨色文字，青绿色表示成功/可用，琥珀色表示待处理，红色只用于危险和失败。使用中文可读字体，小标题和紧凑行距，固定行高与不跳动的状态区域；不做大标题、装饰性渐变、套娃卡片或满屏角色大图。

画像仅用于辨认角色，主信息是名字、稳定 ID和状态。复制、刷新、搜索等工具使用熟悉图标及 tooltip；危险命令保留文字。状态不只靠颜色，均有标签。加载、提交中、超时、无权限、数据过期均有明确反馈；后端不可达时禁用变更，不能用旧状态继续销毁。

并发编辑用版本校验：管理员确认期间角色状态或删除范围变化则重新预检、重新确认，不按旧页面执行。轮询/推送仅更新可观测状态，不重置搜索、翻页、详情页签和未提交输入。

## 实施边界与验收

建议复用现有 `hermes serve` 的认证、profile scope 和 Web 服务入口，不另起代理服务；在确定现有管理入口能力后再决定页面属于现有管理 SPA还是 Pocket 独立管理路由。本稿不预设组件目录或 API实现，也不把尚未支持的状态写成现有接口。

编码前确认：管理认证接入、配置/secret 模板来源、单机管理元数据存储及事务、重新连接/恢复码契约、停止后台任务的范围、删除路径所有权、审计/墓碑/备份保留策略。未来集群需沿用 namespace + profile_id，并把管理权威状态迁入 distributed 方案，不能继续拿本机数据库当共享源。

第一阶段验收：

- 管理认证与角色访问隔离；普通 Pocket 凭证不能调用管理 API，远程入口默认关闭，CSRF/Origin 和管理会话失效覆盖所有写操作。
- 两个角色以真实临时 home 做 A→B→A 验证，列表、创建、激活、签发码、撤销、后台任务和删除无串用，默认 profile 不被隐式纳管或克隆用户数据。
- 并发兑换只成功一次，重签原子废弃旧码，恢复码继续同一 profile 引导，重新连接不覆盖主人，代码与凭证明文不进入列表或日志。
- 生命周期、凭证状态、在线状态独立；未知和失败不显示成功；无声纹服务仍可完成第一阶段激活。
- 管理员删除有二次验证、目标 ID确认和审计；断线可追踪操作，失败保持阻断并可重试，旧凭证和旧备份不能复活角色，其他 profile 不受影响。
- 桌面与手机可完成创建、签发、撤销和人工删除；键盘焦点、对话框关闭/返回、加载与错误反馈可用，所有确认操作显示实际目标。

第二阶段增加声纹绑定状态、服务健康和脱敏自助销毁结果，不开放模板查看/下载或录音回放，也不以动态模型上线为声纹模块前提。
