### 2026-10-12 客户端实施补充（优先于下文旧约定）

创建、激活、重新连接和销毁属于用户自主生命周期，管理员只承担策略、异常处理和有明确权限的强制操作。此前管理员创建与管理员唯一销毁的安排不再作为产品结论；后台视觉稿暂停修改，等待用户审核。声纹延后不必阻塞自助销毁，但第一阶段开放前必须有独立、可靠的主人重新认证与后端完整删除契约，不能拿名字确认或全服务 session token 代替。

现有实现使用全服务 session token，并没有一次性码兑换、角色级访问授权、主人绑定或激活事务。现有 DELETE 接口只移除名字记忆，不是角色销毁。本轮先补客户端静态画像、真实输入/播放音量和播放事件状态，音量以固定标签的静态仪表呈现；并修复无麦克风 API 的文字连接及 Pocket 历史来源筛选。上述改动不构成完整第一阶段验收，独立 profile 激活与主人授权仍须补齐后端契约。

现有桌面端是多窗格工作台，网页仪表盘的聊天是嵌进去的终端。Pocket 不复刻这两套。它只做一件事：对着一个形象说话，并看见字幕。对话仍走已经存在的 `hermes serve`（`/api/ws` JSON-RPC，与 `apps/shared/src/json-rpc-gateway.ts` 相同），语音走现成的听写和朗读，不新造一套代理。

## 产品原则

- 每天只有一个主画面。设置、以前的会话、文字输入都是从主画面拉出来的薄层。
- 第一次激活需要绑定连接码、选形象、起名字、认主和用户自我介绍。第一阶段完成授权绑定和介绍确认即能激活，之后打开即进入对话；声纹采集不作为第一阶段的激活条件。
- 一个连接码只对应一个独立智能体，第一阶段以一个独立 profile 承载。角色名字、主人身份、声纹、记忆和会话都属于该 profile，不与其他角色共享。
- 声纹绑定与识别在第二阶段实现，完成采集同意和绑定后默认开启，由后台判断说话者是否为已绑定的主人。第一阶段不采集声纹、不声称能够识别实际说话者；连接凭证负责访问授权，不能等同于声纹验证。
- 销毁角色是本次新增需求，属于不可逆的身份与数据操作。客户端自助销毁必须由主人完成声纹验证并明确确认，因此随声纹能力在第二阶段开放；第一阶段仅允许管理员后台人工处理，不用普通按钮或文字确认替代主人验证。
- 客户端界面不出现 Hermes 这几个字。字幕上的称呼只用用户起的名字。后台服务名只写在这份设计里，不写进界面。
- 语音默认开着。字幕不是附属，而是和声音一起走的主信息：你说的话、对方正在说的话，都出现在形象下方。
- 形象随客户端自带，不要求先安装 Petdex 宠物。
- 界面文案用中文。点击区域不小于 44px，避开刘海和底部手势条。

## 不做什么

- 主画面不常驻会话侧栏。左上角有入口，打开以后的会话，点进一条再看消息。不做语言模型切换、终端、文件预览、定时任务、多机器人名册。选形象只发生在第一次。
- 不把仪表盘那套终端聊天再画一遍。
- 不做常驻唤醒词（页面开着就是会话，避免手机后台一直听）。
- 第一版不做模型商店，也不让用户自己导入模型。只带一组随包的原创形象，选完就固定，不能中途再换一套商店。
- 不新增核心工具。审批、澄清沿用服务端已有的请求，用一张底部卡片回答，避免回合卡住。

## 第一次使用

后台默认只听本机，并且非本机访问必须带会话令牌；浏览器跨域也不允许任意网站去调它。所以页面由后台同源提供。连接码是短时、一次性的激活凭据，不是长期访问令牌；兑换后由后台签发仅能访问目标 profile 的凭证。手机录音需要浏览器安全上下文，局域网普通 HTTP 地址不能作为麦克风可用的交付前提，部署须提供手机信任的 HTTPS 入口。

第一次按这个顺序，像游戏开场，不要做成设置表单：

1. 连上后台。管理员为一个独立 profile 签发一次性连接码，终端打出手机可打开的地址和连接码（或二维码）。扫码则跳过输入。后台原子兑换连接码并绑定目标 profile，然后请求语音对话所需的麦克风权限；第一阶段不采集声纹，第二阶段另行说明声纹用途和保存范围并征得同意。
2. 选形象。先点一个年龄段：低龄、少年、青年。再横滑该段里的角色。第一阶段点选只改变选中标记和静态画像，不承诺角色动作；第二阶段再考虑选中时的动作和走到前面的表现。
3. 她开口，字幕同时出来，请你帮她起名字。你可以说，也可以打字。她把名字重复一遍。第一阶段点击确认，第二阶段再考虑点头等交互。
4. 认主和自我介绍。她请用户简单介绍自己，例如「我叫……，你可以叫我……」。第一阶段用户通过已兑换连接码的授权凭证确认作为这个角色的主人，后台持久化唯一主人绑定；介绍可以说或打字，称呼与可选介绍由用户核对后保存，不要求身份证、地址等无关信息。这是授权关系绑定，不是对实际说话者的生物识别验证。第二阶段再增加采集同意、随机短句录音、质量检查和声纹绑定。
5. 后台把名字和经确认的主人介绍写入该 profile 的记忆：`MEMORY.md` 保存「我的名字是……，这是用户给我起的」，主人称呼和介绍使用现有用户记忆路径。声纹模板与授权记录单独保存，不进入提示词或普通记忆。记忆是会话开始时冻进系统提示的，所以必须完成认主、落盘并提交激活状态后，才能 `session.create`，第一句就认得双方身份。界面另存同样的角色名字，字幕、标题只用它。
6. 完成。下次打开直接进入主画面。第一阶段设置里可以重新连接，不开放客户端自助销毁；第二阶段声纹能力验收后再加入销毁入口。第一版不提供换人、改名或转让主人；管理员后台删除角色后如需重新开始，须签发新连接码，创建新的独立角色。

第一阶段若朗读、听写或麦克风不可用，起名和自我介绍可打字，完成授权认主后仍可激活并进入文字对话。重复提交和断线恢复不能创建第二个主人或重复兑换连接码。第二阶段声纹采集不依赖听写成功；拒绝采集或服务未就绪时，保留已激活角色和原有文字/语音对话能力，声纹状态保持未绑定，不能执行自助销毁。

### 声纹识别边界（第二阶段）

现有第一阶段角色在升级后，由已绑定主人的授权凭证发起补充采集并明确同意，不重新兑换激活码、不创建新主人或新角色。完成绑定后默认开启识别；不把升级时自动采集或模板缺失视为验证成功。声纹模块与动态模型分别验收，不要求两项同时上线。

- 默认开启后台声纹识别，浏览器只上传音频，不提交可信的「是主人」结论。正常对话标记主人、非主人或无法判定；非主人和无法判定不能修改绑定关系或执行销毁。
- 第一次绑定的授权来自有效连接码及采集同意，不来自角色的回答。声纹比对结果不能由智能体输出、字幕、听写文本或前端状态替代。
- 原始录音默认仅用于当次处理，不长期留存；声纹模板属于敏感生物识别数据，仅在所属 profile 的受控存储中保存，不写入日志、普通会话或模型请求。实现前需确认识别服务、模板保护方式、质量与匹配阈值，以及随机挑战和抗重放能力。
- 普通聊天误拒绝时可重试或使用已授权的文字通道；文字对话不会被视为声纹验证通过。麦克风开关只控制录音，不关闭后台的主人验证规则。第二阶段也不提供绕过声纹的自助销毁或主人重绑。

## 销毁角色（新增需求）

第一阶段不开放客户端自助销毁，由管理员在后台核实申请并人工处理目标 profile 的停止、凭证撤销和数据删除；普通访问凭证不能直接调用销毁操作。这不是声纹验证的替代实现，也不宣称后台已验证实际说话者。

以下为第二阶段客户端自助销毁设计，前置是主人声纹绑定及挑战/抗重放验收通过。入口位于设置薄层，不放在主画面常用操作旁。销毁的是这个独立智能体及其专属数据，不只是隐藏画像或清理浏览器记录；随包原创画像资源不删除，其他 profile 不受影响。

1. 发起时展示角色名字及删除范围，用户可取消。后台确认访问凭证属于目标 profile，生成短时、一次性的销毁挑战，绑定目标角色、当前凭证和本次操作。
2. 请主人朗读随机挑战短句并明确表达销毁意愿。后台同时校验挑战内容、录音新鲜性与抗重放结果、主人声纹匹配；通用聊天中的一段录音或旧的识别成功结果不能重复使用。
3. 验证通过后展示最终确认卡片。只有同一凭证在有效窗口内确认同一角色，后台才原子消费挑战并进入销毁流程。单纯点击按钮、输入「我是主人」或智能体判断均不放行。
4. 销毁开始即禁止新会话和新任务，撤销该角色的访问凭证、未用连接码和待处理挑战，停止该 profile 的活动回合、音频、后台任务并释放其缓存；随后删除专属会话、记忆、主人介绍、声纹模板及角色绑定数据。专属工作区和 profile 配置/密钥的删除范围必须在最终卡片中明确，不删除共享目录或其他 profile 的数据。
5. 后台完成后客户端清除该角色的本地凭证、画像选择和缓存，回到连接页。部分失败保持「销毁中」并拒绝访问，由后台幂等重试，不能只清前端就报告成功，也不能重新激活旧身份。

验证失败、身份无法判定、挑战过期或声纹服务不可用时拒绝销毁，允许重新采样或取消，不降级为文字确认。声纹不是绝对可靠的强认证；挑战和抗重放能力未验收前，不开放自助销毁。备份中的删除时限与恢复后的吊销校验需在实现前确定，不能承诺备份立即擦除；管理员线下恢复不属于客户端自助流程。

## 单机隔离与后续集群

第一阶段先实现单机、基于 profile 的隔离，不等待完整集群。沿用 [分布式 Phase 0](../distributed/phase0-design.md) 的身份约定和 [Phase 2](../distributed/phase2-design.md) 的授权边界，但不提前引入 Redis、对象存储或集群路由。

- **一角色一 profile**：一个连接码绑定一个由后台分配的稳定 `agent_id` / `profile_id`，映射到本机独立 profile home。角色名字只是显示名，浏览器不能用任意路径、名字或 `session_id` 选择 profile。新角色不复用默认 profile 的主人、记忆和历史。
- **连接码生命周期**：管理员创建 profile 并签发连接码；只保存码的哈希、目标身份、有效期和兑换状态。限制尝试频率，原子单次兑换，明文只在签发时展示，不进日志或长期 URL。重新连接由管理员为同一角色签发新的一次性码，不因此创建新角色或覆盖主人。
- **访问凭证与路由**：兑换后的长期凭证单独存储、可吊销，只授权一个 profile。HTTP、WebSocket JSON-RPC、音频、命名、认主、历史查询和销毁都从服务端已认证的绑定解析 profile，并核验会话归属；客户端伪造 profile 或会话 ID 必须拒绝，不能仅在创建会话时隔离。
- **运行作用域**：复用现有 profile scope，在 RPC、音频处理、线程跳转、任务回调、缓存释放及销毁时显式绑定所属 home、secret scope 和 terminal scope。配置、密钥、记忆、`state.db`、声纹和工作区各自隔离；不得依赖进程启动时的全局环境或中途切全局 `HERMES_HOME`。默认声纹开关等行为配置进 `config.yaml`，凭证不进 YAML。
- **单机权威状态**：连接码兑换、凭证吊销、主人绑定及激活/销毁状态须落到本机持久化事务存储，不能只放进程字典或浏览器。它只是单机权威源，不当作未来多节点共享权威库；具体存储与 API 契约设计确认后再定，不另造与 profile 平行的 agents 模型。
- **迁移边界**：本地 `hermes_home_key()` 仅用于 scope/cache，不作为跨节点身份。将来按 `namespace + profile_id` 迁移到 distributed 方案，重新定义连接码、主人及声纹数据的权威源和恢复契约。现有分布式会话快照不包含这些新增数据，不能宣称仅搬会话就完成角色迁移。

profile 是状态隔离单元，不是操作系统安全沙箱。单机方案不因此具备不可信公网多租户的文件、终端和网络隔离能力；若开放此类部署，仍须按 distributed 的隔离与准入要求另行验收。

## 后台管理（新增设计）

Pocket 需要独立于手机对话界面的管理员管理台，第一阶段覆盖独立 profile 创建、连接码签发/撤销、激活进度、访问凭证撤销、管理员人工销毁和脱敏操作记录。以角色列表为首页，不做另一套聊天工作台，不读取会话正文或完整主人介绍。

详细页面、操作流程、管理认证、状态及验收见 [Pocket 后台管理设计](admin-design.md)。普通 Pocket 用户凭证不能访问管理操作；第一阶段管理员人工销毁与第二阶段主人声纹自助销毁明确区分。此方案待确认，本轮不实现后台页面或接口。

## 主画面

竖屏手机：形象在上半部，约占画面一半，居中。第一阶段画像不可动，不以呼吸、眨眼或嘴型承担反馈。下半部是字幕台，最多三行，字大；字幕旁有固定位置的状态和声波区。左上角一个安静的入口「以前」，打开过去的会话列表，点一条看那次的消息，看完返回。底部拇指区只有麦克风开关和上滑提示。没有常驻菜单；设置从当前对话薄层的次级入口打开，第一阶段只承载重新连接等必要操作，第二阶段再加入声纹绑定和自助销毁。

### 第一阶段：静态画像、显式状态与声波

2026-10-12 半双工决策（覆盖此前“直接开口即打断”的约定）：第一阶段在生成回复、准备语音和播放期间暂停自动收音，结束或手动打断后恢复；保留麦克风设备连接及回声消除、降噪请求。点击画像、“停止回复”或按住录音可打断，按住时先停止旧回复再录音。后续再实现“双角色名唤醒打断”：在短时间窗口内识别用户连续呼叫两次角色名，并结合相对环境音量阈值触发；需先选定支持自定义名字的实时识别方案，处理扬声器回放误触发。唤醒词只用于打断，不代表主人身份认证。本次不实现唤醒词识别。

2026-10-12 语音交互补充：角色播放和生成期间，用户可点击画像、按住录音或直接开口打断（麦克风开启时）。打断立即停止本地声音、清空待播队列并取消当前服务端回复。麦克风请求回声消除与降噪，降低角色扬声器声音触发打断的风险。字幕按流式 Markdown 显示；朗读在完整回复结束后解析 Markdown 为纯文本再分句，读正文、链接标签及表格内容，不读格式标记、URL、HTML 或代码块。此阶段优先保证朗读正确性，接受首句语音等到生成完成才开始。

2026-10-12 声波显示补充：输入与播放音量分别使用青色、金色分段振幅可视化，保留双方标签。分段高度由真实实时音量驱动，静音时回落为细点；不以循环动画伪造声音，不将音量包络称为频谱。声波区域高度固定，并支持减少动态效果的系统偏好。

2026-10-12 文本显示补充：字幕、当前对话及历史消息支持 Markdown（含 GFM 表格、列表、链接和代码块），不执行原始 HTML。主画面字幕区最大高度为视口高度的 28%，且不超过 240px，超出后在区内纵向滚动；表格和代码块单独横向滚动。长文本不得持续压缩画像，滚动字幕不触发主画面的按住录音或点击打断。文本更新时仅在用户原本靠近底部时跟随最新内容，用户向上阅读时保持位置。

- **闲着**：状态显示「等你开口」。字幕区空，或留上一句已说完的话，变淡；声波归零。
- **在听**：显示「正在听」；检测到用户讲话时显示带「你」标签的输入声波，识别完成后字幕换成用户原话。等待声音时不伪造讲话动效。
- **在想**：显示「正在思考」，用户那句留在字幕上；不显示讲话声波。
- **在说**：实际朗读开始才显示「正在说话」及带角色名字的输出声波。回答按句子出现，和朗读对齐，不先把整段文字倒出来再开口。这就是混动字幕。只有文字输出或朗读失败时显示「文字回复」，不假装正在播放声音。
- **在等你**：显示「等你确认」，底部卡片承载审批、澄清或主人确认，不依赖画像视线。
- **麦克风关闭 / 连接异常**：显式显示「麦克风已关闭」或「连接已断开」，不把失败伪装成闲着或思考。

用户和智能体声波使用不同颜色及固定标签/位置，不能只靠颜色区分。振幅来自真实输入/播放音频的音量，不来自文字长度或定时假动画；播放结束、暂停、打断和断线立即停止。状态由实际录音、请求和播放事件驱动，字幕、声波与音频共用同一回合生命周期，旧回合不能覆盖新回合。系统开启「减少动态」时改为静态音量/状态指示，仍能区分双方。

你一开口，正在播的声音停下，输出声波清零，状态回到「正在听」并切换用户输入声波。嘈杂环境可以点一下麦克风关掉自动听，改成长按说话；需避免扬声器回放触发自身打断或被当成主人声纹。

横屏或小平板：形象在左，字幕在右，字号和留白随宽度变，不另做一套信息架构。极矮横屏把形象缩小，保证字幕仍在拇指上方可读。

### 第二阶段：动态模型与交互重构

第二阶段做 Live2D 形式的二次元动态角色，技术选型仍沿用 Inochi2D，不表示改用 Cubism。模型就绪后再设计呼吸、眨眼、视线、口型、点击区域和表情，届时可重构交互；第一阶段的真实状态、双方音频和字幕事件契约继续保留。认主、声纹和销毁授权不迁入模型交互，不允许用点头动作替代后台身份校验。

## 触摸

- **点一下身体**：第一阶段闲着时不要求画像动作；正在说时打断，回到在听。第二阶段再考虑看向触点和轻跳反馈。
- **长按**：按住说话，松开就发送。自动听失败时仍能用。
- **上滑**：拉出当前这段对话，底部可打字。打出的字走同一条对话，回复仍朗读并上字幕。更早的会话不堆在这里，从「以前」进去。
- **下滑**：收起这层。
- **点麦克风**：开关自动听。第一阶段显示「麦克风已关闭」，字幕仍在；第二阶段再考虑「捂住耳朵」动作。

第一阶段画像固定，不做成可拖走的挂件，避免挡住字幕；第二阶段形象可以在自己的展示区域内动。

## 这一版怎么接上

页面是 Vite + React，开发时 `npm run dev --workspace @hermes/pocket`，打包后由 serve 在 `/pocket` 提供。现有命名入口为 `POST /api/pocket/name`；新增设计要求它从认证绑定解析目标 profile，并与认主、记忆落盘、激活提交衔接，全部完成后才允许第一次 `session.create`。对话复用 `@hermes/shared` 的 JSON-RPC 客户端，会话来源是 `pocket`，但来源字段不作为身份或授权依据。麦克风在浏览器里录，听写和朗读复用已有音频接口，声纹绑定与验证是新增后台能力，不能假定听写接口已经提供。字幕按句子排队朗读，第一阶段增加显式状态和区分双方的真实声波。Inochi2D 的 WebAssembly 运行时和 `.inp` 留到第二阶段，这一版不带 Cubism，也不带官方示例模型。

### 设计确认与验收

第一阶段编码前先确认：连接码签发/兑换和重新连接契约、凭证与主人授权绑定、单机持久化位置、管理员删除数据范围和备份保留策略。第二阶段再确认声纹服务及采集同意、升级补充采集、验证阈值与抗重放验收标准，以及自助销毁契约。端点、配置字段和存储格式在确认后细化，不在本文把尚未实现的能力写成现状。

第一阶段的行为验收：

- 两个连接码兑换为两个独立 profile；用真实导入和临时 home 按 A→B→A 验证名字、主人、会话、音频、任务及缓存无串用；伪造另一角色的 profile/session ID 一律拒绝。
- 同一码并发兑换只成功一次；过期码拒绝；断线恢复不重复认主，重新连接不覆盖原主人；未完成认主不能创建正式会话，首轮提示已包含角色名字和确认后的主人介绍。
- 无声纹服务、拒绝麦克风权限或仅文字输入均不阻塞授权认主和激活；不采集声纹、不输出实际说话者已验证的结论；普通客户端不能执行自助销毁。
- 管理员后台删除目标角色时停止其任务并撤销所有入口，旧凭证不能复活角色，其他 profile 继续工作；按已确认策略清除本机数据和处理备份。
- 静态画像下可读到正在听、正在思考、正在说话、等你确认及异常状态；双方声波有标签且跟随真实音量，打断后无旧字幕/音频残留；文字降级、减少动态、竖屏与极矮横屏均可用。

第二阶段另行设计确认和验收模型运行时、口型、物理、触点与交互重构，以及声纹绑定、识别和主人确认自助销毁，不阻塞第一阶段静态画像方案。声纹与动态模型可独立交付；声纹验收须覆盖默认开启、已有角色补充采集、跨 profile 模板隔离，以及非主人、无法判定、旧录音、过期/已用挑战、跨角色挑战和服务故障均不能销毁。自助销毁还须验证停止任务、撤销入口、幂等失败恢复和其他 profile 不受影响。
