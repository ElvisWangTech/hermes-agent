# Hermes Pocket：需求与页面方案

> 状态：第一版在 `apps/pocket`，由 `hermes serve` 挂在 `/pocket`。仓库里还没有 `.inp` 模型，所以形象先用随包画像和 CSS 动作，画面接口留着，模型到了再换成 Inochi2D。
>
> 需求与效果图放在本目录（与 `docs/distributed/` 一类的设计文档同级，不进 `website/docs`）。客户端代码在 `apps/pocket`。

工作名 **Hermes Pocket**。

现有桌面端是多窗格工作台，网页仪表盘的聊天是嵌进去的终端。Pocket 不复刻这两套。它只做一件事：对着一个形象说话，并看见字幕。对话仍走已经存在的 `hermes serve`（`/api/ws` JSON-RPC，与 `apps/shared/src/json-rpc-gateway.ts` 相同），语音走现成的听写和朗读，不新造一套代理。

## 产品原则

- 每天只有一个主画面。设置、以前的会话、文字输入都是从主画面拉出来的薄层。
- 第一次使用要做完三件事：连上正在运行的后台、选一个形象、给她起名字。之后打开即进入对话。
- 客户端界面不出现 Hermes 这几个字。字幕上的称呼只用用户起的名字。后台服务名只写在这份设计里，不写进界面。
- 语音默认开着。字幕不是附属，而是和声音一起走的主信息：你说的话、对方正在说的话，都出现在形象下方。
- 形象随客户端自带，不要求先安装 Petdex 宠物。
- 界面文案用中文。点击区域不小于 44px，避开刘海和底部手势条。

## 不做什么

- 主画面不常驻会话侧栏。左上角有入口，打开以后的会话，点进一条再看消息。不做语言模型切换、终端、文件预览、定时任务、多机器人名册。选形象只发生在第一次。
- 不把仪表盘那套终端聊天再画一遍。
- 不做常驻唤醒词（页面开着就是会话，避免手机后台一直听）。
- 第一版不做模型商店，也不让用户自己导入模型。只带一组随包的原创形象，选完就固定，不能中途再换一套商店。
- 不新增核心工具。审批、澄清沿用服务端已有的请求，用一张底部卡片回答，避免回合卡住。

## 第一次使用

后台默认只听本机，并且非本机访问必须带会话令牌；浏览器跨域也不允许任意网站去调它。所以页面由后台同源提供（手机打开局域网地址），令牌只在第一次写入本机。

第一次按这个顺序，像游戏开场，不要做成设置表单：

1. 连上后台。终端打出手机可打开的地址和一次性连接码（或二维码）。扫码则跳过输入。然后允许麦克风。
2. 选形象。先点一个年龄段：低龄、少年、青年。再横滑该段里的角色，点中的那位会动一下。选定后她走到前面。
3. 她开口，字幕同时出来，请你帮她起名字。你可以说，也可以打字。她把名字重复一遍。你点头确认。
4. 名字在打开第一段对话之前写入该 profile 的 `MEMORY.md`（智能体自己的记忆，一句「我的名字是……，这是用户给我起的」）。记忆是会话开始时冻进系统提示的，所以必须先落盘再 `session.create`，第一句就认得这个名字。界面另存一份同样的名字，字幕、标题只用它。
5. 完成。下次打开直接进入主画面。设置里可以重新连接。第一版不提供换人和改名。

若语音还没配好，起名仍可打字，不拦在门外，也不把人丢进一堆配置项。

## 主画面

竖屏手机：形象在上半部，约占画面一半，居中，自己有呼吸和眨眼。下半部是字幕台，最多三行，字大。左上角一个安静的入口「以前」，打开过去的会话列表，点一条看那次的消息，看完返回。底部拇指区只有麦克风开关和上滑提示。没有常驻菜单。

状态只有形象和字幕能看出来：

- **闲着**：轻呼吸。字幕区空，或留上一句已说完的话，变淡。
- **在听**：朝向用户。先显示「正在听」，识别完成后换成你的原话。
- **在想**：轻微摇晃。你的那句留在字幕上。
- **在说**：嘴部或身体随说话起伏。回答按句子出现，和朗读对齐，不先把整段文字倒出来再开口。这就是混动字幕。
- **在等你**：形象看向底部卡片（确认、澄清）。

你一开口，正在播的声音停下，形象回到「在听」。嘈杂环境可以点一下麦克风关掉自动听，改成长按说话。

横屏或小平板：形象在左，字幕在右，字号和留白随宽度变，不另做一套信息架构。极矮横屏把形象缩小，保证字幕仍在拇指上方可读。

## 触摸

- **点一下身体**：闲着时看向触点并轻跳一下。正在说时打断，回到在听。
- **长按**：按住说话，松开就发送。自动听失败时仍能用。
- **上滑**：拉出当前这段对话，底部可打字。打出的字走同一条对话，回复仍朗读并上字幕。更早的会话不堆在这里，从「以前」进去。
- **下滑**：收起这层。
- **点麦克风**：开关自动听。关掉时形象呈「捂住耳朵」，字幕仍在。

形象可以在画面里自己动，不做成可拖走的挂件，避免挡住字幕。

## 形象

随包三套原创二次元女性角色，都没有预先起好的名字。选定并起名之后，界面只称呼这个名字。第一版不能中途换人。

- **低龄**：Q 版。头大身小，年纪更小，服装完整，像陪着玩的小朋友，不做成恋爱对象。
- **少年**：已经画出的这一套。柔和的少年感，短发或长发都还是少女比例。
- **青年**：三位要分开。左边冷一点；中间是御姐，黑色衣装、更成熟的神态；右边阳光，浅色衣服、笑得开。都不是少年那套脸。

圆身体图片已删除。页面上不出现 Hermes。

运行时在手机浏览器里播选中的模型：待机是呼吸、眨眼和头发或衣服的物理；在听、在想、在说、麦克风关掉、在等你，各对应一套表情或动作。说话时嘴型跟着朗读的音量张合，字幕仍按句子出现。点头、点身体走模型上的点击区域。系统开了「减少动态」时停掉物理和弹跳，表情切换还在。

角色画稿必须是可以随客户端发布的原创。Live2D 官方示例模型和 Inochi2D 的吉祥物都不能打进发布包。

## 运行时：用 Inochi2D，不用 Cubism

可以代替。第一版的运行时用 **Inochi2D**，不用 Live2D Cubism。画面仍是二次元纸片人，模型在 Inochi Creator 里绑成 `.inp`。Inochi2D 播不了 `.moc3`，所以不是换一个播放器去放 Live2D 文件，而是换一整条绑骨和运行时。

和版权相关的是两件事，不要混在一起：

- 角色画稿。自己画的原创角色，不碰 Live2D 或 Inochi2D 的版权。不能用的是别人的模型，包括两边的官方示例。
- 运行时协议。Cubism SDK 是专有软件。下载时就要同意其协议。做成产品发布时，还要签发布协议（Publication License）。年销售额低于 1000 万日元的个人和小规模主体，普通应用可以免签、免费用。但「扩展型应用」谁都不能免：让用户自己添加、组合不限数量的模型（形象平台、模型合集）就属于这一类，发布前要审核，一般还要求有收入和分成。我们现在的固定角色、不能导入，大体还算普通应用；一旦以后开放导入或模型商店，就会踩上这条。另外，其费用折扣以在内容里展示 Live2D 标识为前提。

Inochi2D 本体是 BSD 2-Clause。可以放进要发布的客户端，免费，不按收入收费。随包带上它的 LICENSE 即可。不能声称得到官方认可，也不能使用它的标志。用它做出来的模型，版权归画稿和绑骨的人，不归 Inochi2D 项目。

网页端有官方 WebAssembly 运行时（0.9 起随正式版提供预编译包，JavaScript 封装在 `dist/`）。Rust 移植 Inox2D 仍标明是原型，网格组不完整，第一版不用它。发布前要在真实手机浏览器上确认 WebGL2 和嘴型、物理都稳。这是唯一要先验证的技术风险，不是协议风险。

## 这一版怎么接上

页面是 Vite + React，开发时 `npm run dev --workspace @hermes/pocket`，打包后由 serve 在 `/pocket` 提供。名字在第一次 `session.create` 之前写入该身份的 `MEMORY.md`（`POST /api/pocket/name`）。对话复用 `@hermes/shared` 的 JSON-RPC 客户端，会话来源是 `pocket`。麦克风在浏览器里录，听写和朗读走已有的音频接口。字幕按句子排队朗读。Inochi2D 的 WebAssembly 运行时和 `.inp` 还不在仓库里，这一版不带 Cubism，也不带官方示例模型。
